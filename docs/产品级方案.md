# RAG² 产品级方案

> **定位**：极致检索 + 推理编排的下一代 RAG 平台
> **目标用户**：企业知识管理、研究机构、个人工作者
> **核心场景**：海量文档库 → 智能检索 → 报告生成

---

## 一、产品定位

### 一句话
**上传你的文档，问任何问题，得到有依据的答案和结构化报告。**

### 与竞品差异

| 维度 | 传统 RAG（Dify/FastGPT） | RAG² |
|------|--------------------------|------|
| 检索 | dense only | dense + sparse 混合（bge-m3） |
| 分块 | 固定长度 | 递归结构化（保留标题层级） |
| 推理 | 无（检索→生成一跳） | Agent loop（检索→判断→补查→综合） |
| 规模 | 10万级 | 百万级（Qdrant HNSW） |
| 输出 | 单轮回答 | 结构化研究报告 |
| 增量 | 全量重建 | 实时 upsert |

## 二、架构

```
┌──────────────────────────────────────────────────────┐
│                    Web 前端（SPA）                     │
│  文档库管理 │ 检索测试 │ Agent 报告 │ 监控仪表盘       │
└──────────────────┬───────────────────────────────────┘
                   │ HTTP API
┌──────────────────┴───────────────────────────────────┐
│                  FastAPI 后端                          │
│  /upload  /ingest  /search  /report  /metrics         │
├──────────────────────────────────────────────────────┤
│  文档解析层    │  分块层      │  检索层     │  推理层  │
│  PDF/DOCX/HTML │  递归字符   │  Qdrant    │  Agent   │
│  MD/PPTX/XLSX  │  结构化     │  dense+    │  loop    │
│  (7种格式)      │  chunk映射  │  sparse    │  工程    │
├──────────────────────────────────────────────────────┤
│  bge-m3 编码器（dense 1024 + sparse 词项）             │
│  bge-reranker-v2-m3 CrossEncoder                      │
│  DeepSeek-v4-flash LLM                                │
├──────────────────────────────────────────────────────┤
│  Qdrant 向量数据库（HNSW + sparse + payload）          │
│  SQLite 监控（LLM调用/检索/A-B/入库）                  │
│  IndexManager 版本管理                                 │
└──────────────────────────────────────────────────────┘
```

### 技术栈

| 层 | 技术 | 理由 |
|----|------|------|
| 前端 | React + Vite（或 Vue） | 组件化，可维护，替代当前内嵌 HTML |
| 后端 | FastAPI + uvicorn | 异步，自动文档，Python 生态 |
| 向量库 | Qdrant（Docker server 模式） | dense+sparse 原生混合，百万级，实时 upsert |
| 编码器 | bge-m3（FlagEmbedding） | dense+sparse 同步输出，中文优秀 |
| 重排器 | bge-reranker-v2-m3 | 语义消歧，top-30→top-k |
| LLM | DeepSeek-v4-flash（或可配） | 2s/调用，1M 上下文，无审查 |
| 文档解析 | pypdfium2/mammoth/trafilatura 等 | 按格式最优，无 AGPL |
| 监控 | SQLite + 内嵌仪表盘 | 零外部依赖 |

## 三、四个功能模块

### 模块 1：文档库管理

**用户操作**：
- 拖拽上传文件（支持 PDF/DOCX/HTML/MD/PPTX/XLSX/TXT）
- 或输入服务器目录路径批量入库
- 查看文档列表、chunk 统计、入库历史
- 删除/更新文档

**技术实现**：
```
文件 → DocumentParser（按格式分派）→ ParsedDoc
     → RecursiveChunker（512 chars + 64 overlap，保留 heading）
     → QdrantRetriever.upsert_chunks（bge-m3 dense+sparse 编码 + 实时写入）
     → IndexManager 版本注册
     → MetricsCollector 记录
```

- ✅ `src/rag2/ingest/chunker.py` — 递归分块
- ✅ `src/rag2/ingest/pipeline.py` — 端到端管线 + 增量更新
- ✅ `src/rag2/methods/qdrant_retriever.py` — Qdrant upsert/delete

**待补**：

### 模块 2：检索测试

**用户操作**：
- 选择语料库（主语料 / 上传的文档库）
- 输入查询
- 选择模式：混合（dense+sparse+重排）/ 纯 dense / 纯 sparse
- 查看结果：标题、分数、来源标签、文本片段
- 点击结果查看完整文档

**技术实现**：
```
query → bge-m3 编码（dense + sparse）
      → Qdrant 混合搜索（HNSW dense + sparse inverted → RRF 融合）
      → CrossEncoder 重排 top-30
      → 返回 top-k（带 chunk_id + parent_doc_id + heading + page）
```

**已有代码**：
- ✅ QdrantRetriever.search / search_dense / search_sparse
- ✅ /search API 端点（统一格式）
- ✅ 语料选择下拉框

**待补**：
- ❌ 结果高亮（查询词在文档中的位置）
- ❌ 点击结果跳转到完整文档/chunk 上下文
- ❌ 搜索历史

### 模块 3：Agent 报告生成

**用户操作**：
- 输入研究主题
- Agent 自动执行：探索 → 规划大纲 → 逐章检索 → 写作 → 补查 → 综合
- 实时显示 Agent 工作过程（搜索了什么、读了什么、写了什么）
- 输出结构化报告（含引用）
- 导出 Markdown

**技术实现（Loop 工程，非提示词工程）**：
```
run(topic)
├── explore(topic) → search 15 docs → 理解全貌
├── plan_outline(topic) → LLM 规划 3-5 章节
├── for each section:                    ← 代码控制循环
│   ├── gather:
│   │   ├── make_query(section) → str    ← LLM 单步
│   │   ├── search(query) → docs
│   │   └── for retry in range(2):       ← 代码循环
│   │       ├── judge(docs, section) → yes/no
│   │       └── if no: rewrite → search again
│   ├── read(top-3)
│   ├── write_draft(docs) → text
│   └── for followup in range(2):        ← 代码循环
│       ├── extract_gaps(draft) → queries
│       ├── search(gap) → doc
│       └── write_supplement → append
└── synthesize → summary
```

**已有代码**：
- ✅ `src/rag2/agent/rag2_agent_v3.py` — Rag2AgentV3（loop 工程）
- ✅ /report/generate API 端点

**待补**：
- ❌ 前端实时显示 Agent 工作过程（SSE 流式）
- ❌ 报告导出 Markdown/PDF
- ❌ 报告编辑（用户修改 Agent 生成的内容）

### 模块 4：监控仪表盘

**用户操作**：
- 查看成本趋势（7 天 LLM 调用费用）
- 查看延迟分布（检索 P50/P95、LLM P50/P95）
- 查看缓存命中率
- 查看 A/B 测试结果（dense vs 混合）
- 查看入库历史
- 查看最近查询

**技术实现**：

```
  ab_outcomes: 策略/查询/判决/正确/延迟
  ingestion_events: 语料/文件数/chunk数/耗时
```

## 六、关键设计决策

### 1. Qdrant 替代 FAISS
- FAISS IndexFlatIP 是 O(N)，百万级不可用
- FAISS 不支持增量 add，每次全量重建
- Qdrant HNSW 亚线性 + 实时 upsert + dense/sparse 原生混合
- bge-m3 原生输出 sparse，替代手写 grep 倒排索引

### 2. Loop 工程替代提示词工程
- 提示词工程脆弱（agent 听不听看模型心情）
- Loop 工程：代码控制循环结构，LLM 只做单步决策
- 每步是固定代码：search→judge(yes/no)→rewrite→retry
- 可测试、可预测、可调试

### 3. 前端用框架替代内嵌 HTML
- 内嵌 HTML 在不同 webview 里行为不一致
- React/Vue 有统一组件库，兼容性有保证
- SSE 流式需要框架级支持

### 4. 文档解析按格式分库
- 每个格式用最优库（pypdfium2/mammoth/trafilatura）
- 避免 PyMuPDF 的 AGPL 陷阱
- 统一输出 ParsedDoc 格式，下游不感知格式差异
